# 主线任务自动化 · 设计与现状

> 目标：在"游戏自带自动任务"的前提下，中控不抢方向盘，做**看守 + 兜底干预**。

---

## 1. 角色定位（关键决策）

游戏自己会跑自动任务，所以我们**不做驱动器**，做三件事：

| 职责 | 说明 | 频率 |
|---|---|---|
| 感知 | 抓帧 → 锚点 → 状态（主界面/任务面板/战斗/对话/弹窗） | 2–5 Hz，单次 13 ms |
| 判读 | 任务面板 OCR 读「主线-XXX」+「目标」；追踪条读短文本 | 状态变化时按需（~1–3 s/次） |
| 干预 | 只在白名单条件成立时动手（见 §4） | 事件驱动 |

这样即使我们判断错误，也不会把自动任务打断。

## 2. 状态机

```
                 ┌─────────────┐
   panel_teleport│  TASK_PANEL │  ← 面板打开：读标题/目标，可点「马上传送」
   +panel_close  └──────┬──────┘
                        │ 面板关闭
                 ┌──────▼──────┐
   task_btn       │   MAIN_UI   │  ← 主界面：监控追踪条文本变化
   +quest_track   └──────┬──────┘
                        │ 出现战斗/对话/弹窗
                 ┌──────▼──────┐
                 │ BATTLE /    │  ← 待补锚点
                 │ DIALOG /    │
                 │ POPUP       │
                 └─────────────┘
```

判定顺序**面板优先**：面板打开时右侧按钮全被遮住，主界面锚点不可信（已实测踩坑）。

## 3. 锚点清单与状态

| 锚点 | 用途 | 状态 |
|---|---|---|
| `panel_close` / `panel_teleport` / `panel_tab_main` | 任务面板：关/传送/主线页签 | ✅ 跨帧 1.000 |
| `panel_title` / `panel_goal` / `panel_desc` | 面板文本区（OCR 输入） | ✅ 跨帧 1.000 |
| `friend_btn` / `mall_btn` / `event_btn` | 主界面左侧入口 | ✅ 跨帧 1.000 |
| `top_map` / `coord_text` | 场景名/坐标 | ✅ 跨帧 1.000 |
| `chat_area` | 系统消息（掉线/活动提示） | ✅ 跨帧 0.976 |
| `task_btn` / `team_btn` / `quest_track` / `bag_btn` | 主界面右侧 | ⚠️ **待重采**：这 4 个是在"面板打开"时采的，采到的是面板边缘纹理 |

**重采条件**：任务面板关闭 + 主界面无弹窗时，执行
`python tools/bootstrap_anchors.py --spec anchors.spec.json --write`

## 4. 干预白名单（需显式授权）

代码里默认 `ACTIONS_ENABLED = False`，任何输入都会抛 `ActionsDisabled`。
启用：`--enable-actions`。

| 动作 | 触发条件 | 风险 |
|---|---|---|
| 点「马上传送」 | 面板打开 且 标题含"主线" 且 目标非空 | 低（游戏原生功能） |
| 关面板（点 ✕） | 面板打开 且 任务不是我们要做的 | 低 |
| 对话「继续/接受」 | 对话框出现（待补锚点） | 中（可能选错选项） |
| 开自动战斗 | 战斗界面出现（待补锚点） | 中 |
| 关弹窗（背包满/活动） | 弹窗模板命中（待补） | 低 |

## 5. 实测性能（本机 i5-10400 + MuMu NX 15）

```
抓帧（GDI BitBlt, 可被遮挡）      7–11 ms
锚点匹配（10–11 个，ROI 限定）    6–9 ms
单轮 tick                        13–20 ms  → 20 Hz 约 0.28 核
任务面板 OCR（标题+目标）         0.6–2.9 s（含首次模型加载），文本准确率 0.97+
小字号追踪条 OCR                 不稳定（检测阶段常失败）→ 改读面板，不读追踪条
```

## 6. 已踩的坑（都写进代码了）

1. **chrome 高度不是常数**：一次 40 px、换个窗口变 80 px。按"贴底"裁会整体错位 → 用 `align_by_anchors()` 多锚点联合对齐。
2. **自证陷阱**：在同一帧上"裁模板 → 立刻匹配"必然 1.000。必须**跨帧验证**（3 帧，模板从帧 1 裁，帧 2/3 同位置复现）。
3. **面板遮挡**：面板打开时右侧按钮被盖住，采到的模板是面板边缘 → 面板状态下禁用主界面锚点。
4. **负样本用 `np.roll` 是错的**：会把模板绕回画面里，永远满分。改成"把模板原位挖平"。
5. **OCR 分级使用**：大字号面板文本用 RapidOCR（1–3 s）；小字追踪条不可靠；数字/短词走位图模板。
