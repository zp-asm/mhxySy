# 福利 / 升级礼包 / 主线 —— 自动化现状与用法

> 环境：MuMu NX 15 实例 0（960×540），角色 3 级（崔邦昌 / ID 446384247）
> 原则：**默认只读**。任何点击都要 `--enable-actions`；`ACTIONS_ENABLED=False` 时动作抛 `ActionsDisabled`。

---

## 1. 已实现的例行

### 1.1 登录例行（福利 → 刮刮乐 → 升级礼包）

```powershell
python -m mhxy_console.welfare --enable-actions
```

顺序与判据：

| 步骤 | 做法 | 判据 |
|---|---|---|
| 读等级 | 点头像开「人物属性」→ OCR `N级` → 关面板 | 面板上 `3级` 在 (246,56,120,40) |
| 开福利 | 左侧「福利」入口（红点位置） | OCR 找「福利」 |
| 每日福利 | 只在**右上角有红点**时才点 | HSV 红点检测（`red_dot_ratio` 4%~75%） |
| 刮刮乐 | 点「打开刮刮乐」→ 之字形滑动 8 趟 | 卡片区域按「刮刮乐」标题下方 ±200×300 估算 |
| 升级礼包 | 点「升级礼包」→ 按 `1/10/20…120` 只领 ≤ 等级档位 | 每档找「`N级礼包`」再在其右侧区域点「领取」 |

### 1.2 主线看守（自动驾驶）

```powershell
python tools/autopilot.py --seconds 120 --enable-actions
```

| 状态 | 动作 | 冷却 |
|---|---|---|
| `POPUP` | 点「使用」（新手礼包等），无使用则点 ✕ | 1.5 s |
| `CUTSCENE` | 点「手动」推进一句 | 1.2 s |
| `DIALOG` | 点「自动」（只点一次，之后游戏自己跑） | 8 s |
| `TASK_PANEL` | 不在主线页 → OCR 点「长寿迷踪」；有「马上传送」→ 点它 | 3–5 s |
| `MAIN_UI` | 只观察；`--stuck-sec`（默认 30s）无变化才开任务面板兜底 | 20 s |

## 3. 已知不稳的点（都定位到原因）

1. **面板类界面抓帧偶尔拿到旧画面**：MuMu 用 DX 渲染，`BitMlt` 在面板刚弹出的一瞬间可能取到上一帧。
   → 现状：等到稳定 2–3 帧再动作（`stable()`），并保留 PrintWindow 兜底。
2. **面板 ✕ 位置随页签漂移**：主线页 ✕ 在 (846,42)，导引页在 (838,60)，刮刮乐在 (846,31)。
   → 现状：不再依赖 ✕ 固定坐标，状态判定用「任务横幅 / 手动按钮 / 自动按钮」等**每页都有的特征**。
3. **小字号 OCR 不可靠**：追踪条 12px 字经常读成 `回豪师父`。
   → 现状：小字只用来判"有没有变化"；真正的任务名/目标从**任务面板大字号**读（0.97+ 置信度）。
4. **坐标不能写死**：不同页签、不同分辨率都不同。
   → 现状：统一 OCR 找文字再点（`find_text`），锚点只用于"状态判定"。
